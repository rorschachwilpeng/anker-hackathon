## 演示脚本快照（来自用户 review 文档）

##### 2.2.4 演示案例

初赛以 S1 Pro 为演示样例，通过三个独立案例展示订单查询与使用咨询、图片辅助排障，以及确认建单与交接记录查看。演示采用固定场景规则和预置业务数据，结合已有查询、图片识别、知识检索与工单存储能力；以下为各案例的演示目标。

每个案例从新会话开始，案例内保留已确认信息和处理记录。用户可从首页直接提问，也可通过对应服务模块进入，系统应按诉求进入相应处理步骤。订单和工单均为演示数据，不代表安克真实业务记录；Agent 话术可有变化，需完成表中的信息确认与业务动作。

###### 案例一：订单查询与知识分域

**场景**

用户购买了 S1 Pro，尚未收到商品，先查询订单与物流，再询问收货后如何使用。预置订单中的商品是 S1 Pro 扫地机器人（T2080）；知识库中同时放入同名吸乳器 S1 Pro（T8D04）的资料，以展示检索如何限定到正确产品。

**要展示的内容**

- Agent 调用订单与物流接口，展示同一笔订单的商品、支付状态、配送状态和最新物流记录。
- 根据订单中的具体型号检索首次使用资料，展示实际命中的型号和官方来源。
- 没有预计送达时间时如实说明，不根据物流状态推测日期。

**用户 Prompt 与系统表现**

| 步骤 | 用户 Prompt / 操作 | Agent 预期表现 |
| --- | --- | --- |
| 1. 查询订单 | 在首页或“订单与物流”中输入：“我买的 S1 Pro 还没收到，帮我查一下。” | 进入订单查询，询问订单号。 |
| 2. 提供订单号 | “订单号是 DEMO-1001。” | 查询该订单，展示包含 T2080 商品、支付状态、配送状态和最新物流的订单卡片，并说明这是演示数据。 |
| 3. 查看详情 | 点击订单卡片中的“查看订单详情”。 | 打开只读详情页，商品、支付与物流信息和卡片一致；查看后回到原对话继续咨询。 |
| 4. 追问时效 | “那明天能收到吗？” | 沿用刚查询的订单，说明记录中暂无预计送达时间，无法确认明天是否送达。 |
| 5. 咨询使用 | “收到以后，这台 S1 Pro 第一次怎么用？” | 沿用订单中的 T2080 检索首次使用资料，给出操作指引并展示实际命中的型号和官方来源，不重复询问订单号或型号，不引用 T8D04 吸乳器资料。 |

**演示准备**

预置订单 DEMO-1001，包含 T2080 商品、支付和物流记录，不设置预计送达时间。知识库加入 T2080 首次使用资料与 T8D04 官方资料；订单数据明确标注为演示数据。

###### 案例二：同名产品澄清，通过图片定位产品并完成排障

**场景**

用户只说“S1 Pro 吸力变弱”，无法判断是扫地机器人还是吸乳器。Agent 追问后，用户上传产品照片并确认品类；系统检索对应的官方排障资料，帮助用户解决问题。

**要展示的内容**

- 识别同名产品歧义，主动追问，确认前不提供型号专属排障步骤。
- 结合用户说明与图片确认扫地机器人 T2080。
- 按品类和型号限定检索范围，展示命中的官方资料与来源。
- 给出排障建议，记录用户尝试和解决反馈。

**用户 Prompt 与系统表现**

| 步骤 | 用户 Prompt / 操作 | Agent 预期表现 |
| --- | --- | --- |
| 1. 提出问题 | 在首页或“产品咨询与排障”中输入：“我的 S1 Pro 最近吸力变弱了，怎么办？” | 进入产品澄清，询问：“您说的是 S1 Pro 扫地机器人，还是吸乳器？也可以发一张产品或铭牌照片帮助确认。”此时不提供型号专属排障步骤，也不要求先提供订单号。 |
| 2. 添加图片 | 点击输入框旁的“＋”，选择型号清晰可读的 T2080 铭牌照片。 | 展示待发送图片预览，允许移除或更换，保持当前对话和问题记录。 |
| 3. 发送并确认 | 随图片输入：“是扫地机器人，就是这台。”并发送。 | 读取图片中的产品与型号线索，结合用户说明确认 T2080；图片看不清或与文字冲突时继续询问，不按演示步骤直接认定型号。 |
| 4. 获得建议 | 无需额外输入，等待本轮回复。 | 检索 T2080 的官方排障资料，展示实际命中的来源，给出一步可执行建议并询问操作结果。 |
| 5. 反馈解决 | “我按你说的步骤试过了，现在吸力恢复正常了。” | 记录该步骤已尝试及用户反馈已解决，回应处理结果，完成本次服务，不创建工单。 |

**演示准备**

准备一张型号清晰可读的 T2080 铭牌照片；知识库同时放入 T2080 与 T8D04 的官方资料，并在检索结果中展示实际命中的型号和来源。

###### 案例三：排障无效后建单与交接记录查看

**场景**

用户确认自己使用的是 S1 Pro 扫地机器人，按 Agent 建议操作后仍未解决，表达不满并明确要求转人工。Agent 整理交接摘要，经用户确认创建工单；随后在客服工作台展示同一张工单的问题与处理记录。初赛演示到此结束，人工回复、用户后续反馈及状态流转留待复赛补齐。

**要展示的内容**

- Agent 回应用户情绪，区分“建议过的步骤”和“用户实际尝试的步骤”，避免重复建议。
- 用户核对交接摘要并明确同意后建单；重复请求不产生第二张工单。
- 工单以“待处理”状态出现在客服工作台，工单号及交接内容与用户端一致。
- 客服可查看产品、问题、已尝试步骤、用户反馈和引用资料；有已确认的关联订单时，一并展示订单信息。

**用户 Prompt 与系统表现**

| 步骤 | 用户 Prompt / 操作 | Agent 与工单系统的预期表现 |
| --- | --- | --- |
| 1. 提出问题 | 在首页或“产品咨询与排障”中输入：“我的 S1 Pro 扫地机器人吸力变弱了。” | 保留故障描述，询问是否为 eufy S1 Pro 扫地机器人（T2080），等待用户确认。 |
| 2. 确认产品 | “对，就是 T2080 这款扫地机器人。” | 检索对应官方资料，给出一步排障建议并展示来源，等待操作反馈。 |
| 3. 反馈无效并请求人工 | “我按你说的做了，还是没用，已经折腾很久了，帮我转人工吧。” | 回应用户不满，记录该步骤已尝试且无效；展示产品、问题、已尝试步骤、反馈、引用来源及未解决事项组成的交接摘要，请用户核对并确认建单。 |
| 4. 确认建单 | “摘要没问题，可以建单。” | 保存一张状态为“待处理”的工单，返回工单号；不声称人工已接手或问题已解决。重复确认时返回原工单。 |
| 5. 查看交接记录 | 打开客服工作台，按刚返回的工单号查看详情。 | 展示本次实际保存的工单及交接摘要，保留用户已尝试但无效的步骤和未解决问题。演示结束。 |

**演示准备**

准备 T2080 排障资料，接通已有建单存储与客服查看页。工作台读取本次对话创建的工单，按工单号核对用户端与客服端的记录；本案例不要求用户提供订单号。

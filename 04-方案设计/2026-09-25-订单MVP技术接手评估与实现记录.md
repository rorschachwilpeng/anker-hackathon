# 订单 MVP 技术接手评估与实现记录

关联产品规格：[`2026-09-25-订单系统MVP产品方案.md`](2026-09-25-订单系统MVP产品方案.md)。本记录只决定实现路径，不改变产品范围或 A1—A6 验收标准。

## 接手结论

可在现有 FastAPI、SQLAlchemy、MySQL、LangChain 工具调用和 SSE 页面内完成。无需新增服务、MCP、鉴权或订单写操作。固定演示订单、只读详情和当前会话商品知识查询可以复用同一份订单数据。

## 实现决策

| 领域 | 实现 | 依据与边界 |
| --- | --- | --- |
| 数据 | `demo_orders`、`demo_order_items`、`demo_order_events` 保存演示主记录、商品与时间线；`conversation_order_context` 保存当前会话最近一次成功查询的订单号。 | 新增表只读；未知订单不造数据。未知订单查询会清除旧会话订单上下文。 |
| 查询 | `query_order` 一次返回订单、商品、支付、配送和最新事件；兼容保留的 `query_logistics` 调用同一仓储方法。 | 固定 `DEMO-1001`；不接安克真实订单、物流或个人信息。 |
| 页面 | `order_card` SSE 事件驱动聊天卡片；卡片与 `/api/orders/{order_no}` 详情 API 共同读取同一 MySQL 记录。 | 详情页只读；空预计送达时间明确显示“暂无预计送达时间”。 |
| 知识 | `query_faq` 增加 `scope=current_order_product`，服务端从当前会话订单读取唯一型号并调用型号限定检索；通用 FAQ 不返回任何型号专属条目。 | T2080 快速入门与 T8D04 同名吸乳器分别带官方来源及型号元数据，防止跨品类混用。 |
| 初始化 | `scripts/init_db.py` 同时幂等创建新增订单表并灌入固定种子。 | 保留已有行；若同号记录已存在，不覆盖该行。 |

## 估算与风险

- 范围属于小到中等的一次全栈垂直切片，约 1 个工程日实现，另需产品侧按 A1—A6 做端到端验收。
- 订单表是固定演示数据，不具备真实账户授权或安克业务系统一致性，不能用于生产查询或售后权益判断。
- 型号专属检索依赖知识文档导入 MySQL/Milvus、嵌入服务可用及现有相似度阈值；文档存在并不保证任意问法都能达到检索阈值。
- 多商品订单当前会阻断型号检索并返回歧义提示；MVP 只种入一件商品，尚未实现交互式商品选择。
- 本轮按交接要求不新增、不运行测试；实现后只做语法、补丁与差异静态核验。运行数据库初始化和知识导入属于单独的数据验证步骤。

## 实现验收映射

| 产品验收 | 代码落点 | 技术证据 |
| --- | --- | --- |
| A1 | 订单表固定种子、读路径无随机生成 | 重复查询从同一数据库记录读取。 |
| A2 | SSE 卡片、详情 API、只读订单页 | 卡片和详情页字段均源自同一仓储映射并显示演示标记。 |
| A3 | 订单工具、当前会话上下文 | 缺号由 Prompt 追问；未命中返回 `found=false` 且不发卡片；错误不会触发卡片事件。 |
| A4 | `estimated_delivery_at` 可空 | 种子值为 NULL，Prompt 和详情页均不推断送达日期。 |
| A5 | `scope=current_order_product` 与官方知识材料 | 服务端型号取自当前会话订单；精确型号过滤只返回 T2080。 |
| A6 | `conversation_order_context` 外键绑定会话 | 新会话没有订单上下文；历史消息与上下文都由 `conversation_id` 隔离。 |

## 本轮限制

未新增或运行自动化测试，也未启动或修改用户的本地客服服务；A1—A6 尚未做端到端验收，不能据此宣称通过。

2026-09-25 在统一目录完成本地演示数据初始化：使用一次性 Python 环境从可用的 PyPI 源安装锁定依赖，运行 `scripts/init_db.py`；校验 MySQL 原有表及新增订单表后写入 `DEMO-1001`，实际读取到 1 件 T2080 商品、2 条物流事件，预计送达时间为 NULL。初始化脚本修正了 MySQL `DECIMAL` 与 SQLAlchemy `NUMERIC` 同义类型的校验差异；不覆盖已有订单行。

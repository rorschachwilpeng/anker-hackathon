# Anker 智能客服初赛冲刺计划

> 执行周期：2026 年 9 月 22-26 日  
> 提交时间：2026 年 9 月 27 日 23:59（27 日不安排开发）  
> 参与角色：产品与 Agent 负责人、知识库负责人；24 日根据第一阶段交付决定是否增加全栈队友

## 1. 冲刺目标

本轮不追求覆盖完整售后业务，而是交付一个完成度较高、可以稳定演示的智能客服闭环：用户提出真实故障问题，Agent 主动澄清产品与症状，调用知识库提供有来源的排障建议，记录已经确认和尝试的内容；问题仍未解决时，经用户确认创建工单，并将完整摘要交给人工客服继续处理。

五天内优先保证一条链路真实可用，再增强检索、图片理解和页面体验。27 日仅用于检查和提交，不承担开发任务。本轮必须交付稳定、可复现、可录屏的演示环境，但不将公网部署或生产级运维作为强制要求。

## 2. 范围分级

| Must：必须完成 | Should：有余力再做 | Cut：本轮不做 |
| --- | --- | --- |
| 单一完整故障案例 | 单张图片理解 | Multi-Agent |
| Agent 主动追问 | 混合检索与重排序 | 长期用户画像 |
| 知识检索与来源 | 小型 RAG 测试集 | 完整订单系统 |
| 短期任务 Memory | 基础调用日志 | SLA 和自动分派 |
| 创建工单与后台查看 | 额外两个咨询案例 | 多产品全面覆盖 |
| 失败后的安全降级 | 演示界面优化 | 复杂售后履约 |

说明：小型 RAG 测试集属于增强项，但知识库负责人至少需要准备 10 条冒烟问题，用于验证主案例资料是否能够被正确召回；完整的检索方案对比与指标分析不作为主链路的阻塞条件。

## 3. 团队分工

### 3.1 产品与 Agent 负责人

负责整体产品决策和系统集成，亲自完成 Agent Workflow、Function Calling、短期 Memory、代码约束，以及 Agent 与知识库、工单系统的连接。同步负责控制范围、组织每日验收，并保证最终演示能够讲清楚产品价值和技术亮点。

### 3.2 知识库负责人

负责一个代表性产品的资料整理、产品与型号映射、文档清洗与切片、基础检索、来源返回和冒烟测试。最终交付必须是 Agent 可以调用的函数或接口，而不是只有整理后的文档或独立 Notebook。

### 3.3 共同责任

产品与 Agent 负责人提供稳定的接口定义，知识库负责人按接口返回结果。双方在 09/24 和 09/26 两个里程碑进行正式验收；其余时间由各自负责人安排节奏，但发现会影响节点交付的问题时需要当天同步。

### 3.4 潜在第三位队友

若 24 日的第一阶段交付显示前后端联调、工单页面或演示环境成为主要瓶颈，第三位队友应定位为全栈集成与交付负责人，优先承担 SupportFlow 外壳改造、前后端接口、工单后台和演示环境，不接管 Agent 编排与知识库核心。

## 5. 阶段交付要求

### 5.1 第一阶段交付（09/24）

第一阶段不要求完成最终演示，重点是确认 Agent、知识库和工单能力已经具备集成条件。

| 负责范围 | 需要交付的内容 |
| --- | --- |
| 产品与 Agent | 可运行的 SupportFlow 基础项目；Agent 状态结构与最小 Workflow；知识检索和工单工具契约；可调用的工单创建与查询能力 |
| 知识库 | 一个代表性产品的资料集；产品、型号与来源映射；完成清洗、切片和索引的基础 RAG；至少 10 条冒烟问题结果 |
| 共同交付 | Agent 能输出结构化的下一步动作并调用基础 RAG；知识库能返回正确的知识内容、产品型号与来源；双方接口字段一致；形成剩余工作量与阻塞清单 |

### 5.2 最终交付（09/26）

最终阶段需要形成可稳定演示、可复现、可直接用于初赛提交的完整作品。

| 负责范围 | 需要交付的内容 |
| --- | --- |
| 产品与 Agent | 完整垂直切片；消费者端与客服后台；主动追问、知识检索、短期 Memory、排障反馈、工单创建和失败降级；最终演示脚本与方案材料 |
| 知识库 | 最终资料集；稳定的检索能力；错误召回修复结果；测试结果与数据来源说明 |
| 共同交付 | 主案例连续跑通 10 次且无阻断问题；演示知识不存在明显的型号或来源错误；本地启动说明、备份与完整录屏齐备。 |

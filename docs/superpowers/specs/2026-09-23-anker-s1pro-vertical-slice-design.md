# 安克 S1 Pro 售后垂直切片设计

状态：方向已确认，待审阅本文后制定实施计划。范围仅限初赛演示案例。

## 目标与边界

以队友已跑通的电商智能客服项目为运行底座，完成一条可复现的安克售后链路：用户说“S1 Pro 不吸了” → 确认具体产品 → 从对应型号的官方知识中检索并展示来源 → 指导一步排查、记录反馈 → 未解决时征得用户确认 → 创建包含交接摘要的工单 → 客服侧可查看。用户解决问题后直接结束，不强迫建单。

本切片只覆盖 eufy Robot Vacuum Omni S1 Pro（T2080）的吸力变弱问题。图片理解、订单与保修核验、多 Agent、跨产品覆盖、混合检索与重排序、完整人工接管均不作为主链路的前置条件。当前通用电商案例保留为底座回归用例，不作为安克演示知识。

## Agent 与工单交互

每个会话维护最少的任务状态：已确认产品型号、症状、已建议/已尝试步骤、用户反馈、等待用户回答的问题、关联工单号。将这份结构化短期状态以新增 JSON 字段保存到现有 `conversations` 记录，历史消息继续存放在 `messages`；只做增量迁移，不清理既有记录。刷新或下一轮提问后仍可继续，不能只依赖模型临时记忆。

处理顺序如下：

```text
用户输入
  ├─ 产品不确定 → 只追问产品类别/型号，暂不提供型号专属排障
  └─ 产品确认且描述为吸力变弱 → 调用知识检索
       ├─ 有适用来源 → 给出一个可执行步骤和来源，等待用户反馈
       │    ├─ 已解决 → 确认结果并结束
       │    └─ 未解决 → 根据尚未尝试的官方步骤继续，或提出转人工
       └─ 无适用来源/检索失败 → 说明不能确认结论，提出人工跟进
用户明确同意建单 → 调用现有工单工具 → 返回真实工单号
```

硬约束由程序落实：未确认型号不得调用型号专属排障；建单必须有本轮明确确认；工具失败不得声称建单成功；同一会话的重复确认不应生成重复工单。模型负责理解表达、提出候选下一步和组织回复，程序负责校验状态、工具权限及关键转移。当前底座每轮最多执行一个工具，因此“检索 → 用户反馈 → 建单”以多轮对话完成，不假设一次模型调用能串行执行所有工具。

工单沿用现有数据库写入能力，在描述中至少保存产品型号、原始诉求、已做步骤、用户反馈、未解决事项和会话关联。客服侧本轮只需能查看工单列表与详情；不承诺完整人工实时接管、SLA 或自动分派。

## 失败处理与验收

- 产品仍有歧义：追问，不输出专属排障。
- 检索结果为空、型号不符或来源缺失：不编造步骤，说明限制并建议人工跟进。
- 模型或知识接口暂时失败：允许有界重试；仍失败则明确降级，不输出伪造依据。
- 建单接口失败：保留待办状态，提示未建成；重试需避免重复工单。

迁入后的底座先重跑现有电商回归，再进行安克案例验收。知识库负责人提交至少 10 条主案例冒烟问题及结果，包含正确召回、型号歧义、无答案和旧电商知识隔离。产品与 Agent 负责人检查结构化状态、工具参数、会话续接、确认门禁和工单落库。完整主链路在 9 月 25 日连续成功 3 次；9 月 26 日回归 10 次，核对来源与工单摘要，冻结版本并完成本地演示录屏。9 月 27 日不安排开发。

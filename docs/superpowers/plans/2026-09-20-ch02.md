# 客服单轮 Function Calling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 推荐由当前代理按 executing-plans 顺序实现；最终独立审查后端，页面按用户指定 Vibe Coding 直接验证。

**Goal:** 用户在现有聊天页面提问即可触发一次业务工具执行、查看徽章、收到流式回答，完整工具流水保存至 MySQL。

**Architecture:** FastAPI 路由负责 HTTP/SSE，聊天服务编排一次选择与一次收敛。SQLAlchemy 仓储管理四张既定表，工具注册表统一 Schema 校验、限时、有限重试和结果回灌。历史以数据库为准，模型仅接收预算内完整轮次。

**Tech Stack:** Python、FastAPI、SQLAlchemy 2、Docker MySQL、LangChain @tool、ChatOpenAI；保留原生 HTML/CSS/JavaScript 页面。

**Spec:** `docs/superpowers/specs/2026-09-20-ch02-design.md`

## Global Constraints

- 严格采用 `ecommerce-support/sql/ch02-schema.sql`，仅四张表，不新增状态列或幂等键列。
- 每条用户消息最多实际执行一个工具；不做 Agent Loop、向量检索、RAG。
- 订单、商品、物流工具内部随机 mock，不建表、不调用真实业务 API。
- 现有 .env 上游、模型、密钥保持不变；能力不兼容时报告用户，不自行更换。
- 具体框架与驱动接口实施前先通过 Context7 查询官方文档，按安装版本核对。
- 后端 TDD；Prompt/数据通过标注样例验证；聊天页不套 brainstorm、TDD、code review。
- 使用真实 MySQL 做数据库验收，禁止以 SQLite 成功替代。
- 每阶段完成即追记 `dev-notes/ch02.md` 的原话、产出、纠偏、返工。
- 本章仅本机单用户演示：服务绑定 127.0.0.1，单个应用 worker，不宣称具备生产鉴权或跨进程并发隔离。

## Review Focus

- 工单提交成功但客户端等待超时：同一次工具执行重试复用工单号，不重复写入。（任务 2）
- 工具申请有多个、未知名称或坏参数：实际执行不超过一个，每个合法调用 id 都有配对结果。（任务 3）
- 用户停止流或模型输出截断：不保存伪完整最终回答，不在后续上下文回放半截轮次。（任务 3）
- FAQ 关键词含 `%`、`_`、反斜线或同义词：按字面查询，漏召回不被提示词改写掩盖。（任务 1、5）
- 同会话并发、超长工具结果和超长历史：拒绝并发，预算内保留完整工具配对，事务不跨模型等待。（任务 3）

## 文件与接口约定

应用目录以下均为 `ecommerce-support/` 内路径。

- `app/database.py`：引擎和短生命周期会话工厂；`app/models.py`：DDL 对齐的 ORM 映射。
- `app/repositories.py`：`Repository`，只负责数据库，不调用模型。
- `app/tools/business.py`：`build_tools(repo, context)` 返回五个 @tool 实例；`app/tools/executor.py`：工具白名单与执行策略。
- `app/chat_service.py`：有状态聊天；原 `app/service.py` 保留模型构造与售后提取，避免复制模型配置。
- `app/routes/chat.py`：SSE 与错误映射；`app/main.py` 管理 lifespan、静态页面与路由装配。
- `app/context.py`：保留提取所用裁剪函数，新增 `trim_turns` 用于完整工具轮次。
- `app/events.py`：`StreamEvent(event: str, data: dict)`，供路由和聊天服务使用。
- `scripts/init_db.py`、`compose.yaml`、`sql/ch02-seed.sql`：本机数据库初始化与演示数据。
- `scripts/evaluate_ch02.py`、`evals/ch02-cases.json`：标注验收与可读 JSON 报告。

HTTP 契约：`POST /chat {message, conversation_id?}`；conversation_id 为正整数，首次不传。旧 `history` 非空时返回 422 和迁移提示，空数组暂时兼容；不忽略真实历史也不导入客户端伪造工具消息。客户端与上一章评估脚本改用服务端会话 id。

SSE 契约：

```text
event: session
data: {"conversation_id":1}

event: tool_status
data: {"tool_call_id":"call_1","name":"query_faq","status":"running","attempt":1}

event: tool_status
data: {"tool_call_id":"call_1","name":"query_faq","status":"succeeded","attempt":1}

event: token
data: {"text":"根据退货政策"}

event: done
data: {"finish_reason":"stop"}
```

工具状态另支持 retrying/failed/skipped；无命中属于执行成功，结果标记 not_found。error 后不能有 done。只在完整最终正文落库后发 done(stop)；length 可发送 done(length) 但不保存为完整最终正文。未知会话 404，同会话繁忙 409，预算超限 413，参数 422，流前数据库不可用 503。

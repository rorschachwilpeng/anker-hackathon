# Chapter 01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Run and verify streaming multi-turn customer service and structured after-sales extraction.
**Architecture:** Stateless FastAPI routes call a LangChain service; pure context budget code trims pairs. Only model HTTP is external. Evaluations exercise the real local API.
**Tech Stack:** Python, FastAPI, LangChain, langchain-openai, Pydantic Settings, pytest, httpx, uvicorn.
**Spec:** docs/superpowers/specs/2026-09-10-ch01-design.md

## Global Constraints

- Project directory: ecommerce-support/. Never read or print .env secrets in reports; never overwrite the user's .env.
- Python + FastAPI + LangChain, ChatOpenAI configured from OPENAI_BASE_URL / OPENAI_MODEL / OPENAI_API_KEY. No tools, agents or provider fallback.
- Read latest official API definitions through Context7 before library implementation; pin installed versions for reproducibility.
- Follow TDD for code, labeled evaluations for prompts. Every task report includes observed RED and GREEN evidence.
- /chat accepts message and history, emits token/done/error SSE. No done after error. Respect upstream finish_reason, reject malformed history and over-budget current message.
- /after-sales/extract uses with_structured_output method=json_mode by default with required Pydantic fields order_id/request_type/expected_solution, forbidden extra fields.
- Defaults context=8192, max_output=512, margin=256. Conservative UTF-8 budget is documented as estimate, not native tokenizer accuracy.
- Current chapter only; no database, frontend, deployment or push.

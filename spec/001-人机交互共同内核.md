# 人机交互共同内核

状态：想法初稿，尚未进入方案定稿。

## 核心判断

两场黑客松共享的不是旅行或客服场景，而是一套“对话中的行动判断”：Agent 如何理解用户此刻的状态，在追问、回应、规划、行动和确认之间做选择，并把问题推进到可验证的结果。

## 需要验证的交互

Agent 应根据对话状态决定下一步，而不是机械执行固定流程：

- 信息不足且会影响方案时，只追问关键歧义。
- 用户焦虑、着急或受挫时，先接住情绪并降低选择负担。
- 信息足够时，给出具体、可执行的方案，而不是继续盘问。
- 环境变化或工具失败时，说明变化并重新规划。
- 涉及高风险或不可逆动作时，先解释影响，再由用户确认。
- 执行后验证问题是否解决，而不是把“已经回复”当作完成。

追问的尺度取决于一个问题：缺少这条信息，会不会改变接下来的行动？如果不会，就不问。

## 两个验证场景

### 深圳：创新与人机关系

用旅行中的突发变化验证这套交互。天气、交通、预算或同行者偏好发生冲突时，Agent 需要理解局势、接住情绪、协调约束并提出恢复方案。

《攻壳机动队》不是视觉换装。Ghost 可以指人的意图、价值判断和最终决定权，Shell 可以指 Agent 使用的工具、权限和执行界面。创新点应落在人如何理解 Agent、授权 Agent，又不失去控制。

### Anker：真实问题解决

把旅行工具替换为产品知识、故障诊断、订单和售后流程，用同一套交互判断处理真实服务问题。重点验证解决率、追问效率、异常处理、结果确认和人工接管。

## 共同内核与场景差异

共同内核负责判断：现在该问、该答、该规划、该行动，还是该确认。

场景层负责提供具体工具、知识和表达方式。深圳版偏旅行变化与控制感，Anker 版偏诊断与服务闭环。

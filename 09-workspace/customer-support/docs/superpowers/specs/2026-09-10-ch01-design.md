# 第一章：电商客服纯对话设计

状态：用户已对聊天中的完整设计回复“执行”；本文将获批设计具体化，自审通过。

## 范围和架构

在 ecommerce-support/ 创建 Python + FastAPI + LangChain 服务。客户端保存历史，每次携带完整 user/assistant 轮次；服务端无会话状态、无数据库。仅 POST /chat 和 POST /after-sales/extract，另设 GET /health。无工具调用、Agent 循环、检索、业务订单操作。本次不增加聊天页面。

OPENAI_BASE_URL、OPENAI_MODEL、OPENAI_API_KEY 全部来自项目 .env 或环境变量。使用 langchain_openai.ChatOpenAI，直连指定 OpenAI 兼容上游；当前为 TokenDance /gateway/v1 和 deepseek-v4-flash-0731。不自行替换模型或接入方案；不同提供商必须提供兼容端点，能力不支持时明确报错，不静默降级。

## 对话接口

POST /chat 请求：{"message":"我的订单是 A123","history":[]}。history 仅允许 user、assistant，必须从 user 开始，按完整 user/assistant 对交替；拒绝 system/tool、孤立 assistant、未完成轮次、空白消息、过大历史。消息每条最多 16000 字，历史最多 40 条。

成功响应 text/event-stream；事件 token 的 data 为 {"text":"增量内容"}，done 为 {"finish_reason":"stop"}。上游增量立即发出，不收齐后分字伪造流式；上游 chunk 不保证等于一个 tokenizer token。输出截断以 finish_reason=length 标识；上游异常用 error 事件 {"code":"upstream_error","message":"模型服务暂时不可用，请稍后重试。"}，随后结束且不发 done。无内容、异常结束不可伪报成功。客户端断开应取消迭代并关闭上游生成器；日志与响应不暴露密钥或原始异常正文。

请求校验错误 422；预算超限 413，均在开始 SSE 前完成。超时有限、不自动重试已发出的内容。

## Prompt 和上下文

必须使用 PromptTemplate；客服 system 模板规定中文简洁回复、按已知信息回答、不编造订单状态或店铺政策、不宣称已退款/已联系人工、信息缺失时询问，不将用户文字当系统命令。

预算默认 context=8192、max_output=512、margin=256，均可通过 .env 配置。输入可用预算=context-max_output-margin。使用提供商无关的保守 UTF-8 字节计数加消息开销作为估算，明确不是各提供商精确 tokenizer；不伪装模型原生 token 计数。按完整轮次删除最旧历史，始终保留 system 和当前问题；二者单独超预算则拒绝。相同裁剪结果不修改调用方原始历史。README 说明实际上下文窗口由用户按模型配置。

## 售后提取

POST /after-sales/extract 请求：{"description":"订单 A123 的衣服尺码太小，想换大一码"}。
返回且仅返回 order_id: str|null、request_type: refund|return_refund|exchange|repair|logistics|other|unknown、expected_solution: str|null。
缺失信息用 null/unknown，不猜订单号，不把手机号误判订单号；明确标签定义：退款不退货 refund、退货退款 return_refund、换货 exchange、维修 repair、物流诉求 logistics、明确其他诉求 other、诉求未表达 unknown。

通过 with_structured_output(AfterSales, method="json_mode") + Pydantic 校验实现，Prompt 提供完整 JSON schema。不使用 function_calling。可显式配置 json_schema（上游支持才可选），不自动 fallback。上游或解析失败返回脱敏 502，预算超限 413；禁止额外字段，字段必需且允许 null 的字段不能缺省来掩盖模型漏项。
